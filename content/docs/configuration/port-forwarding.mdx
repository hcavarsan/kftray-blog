---
title: Port Forwarding
description: Configure TCP and UDP port forwards with automatic reconnection, custom local addresses and workload targeting for Kubernetes services.
---

Port forwarding lets apps on your machine connect to Kubernetes services. kftray manages the connections and reconnects when they drop.

## TCP forwarding

```json
{
  "service": "api-gateway",
  "namespace": "production",
  "local_port": 8080,
  "remote_port": 80,
  "context": "prod-cluster",
  "alias": "Production API"
}
```

This forwards `localhost:8080` to port `80` on the `api-gateway` service in the `production` namespace. You can reach the service at `http://localhost:8080`.

TCP is the default protocol. It works for HTTP, databases, gRPC and most other services.

## UDP forwarding

```json
{
  "service": "dns-service",
  "namespace": "kube-system",
  "local_port": 5353,
  "remote_port": 53,
  "context": "dev-cluster",
  "protocol": "udp",
  "workload_type": "proxy"
}
```

UDP forwarding needs the `kftray-server` proxy component running in your cluster. See [proxy forwarding](/docs/configuration/proxy-forwarding) for setup details.

<Callout type="info" title="UDP requires proxy mode">
UDP port forwards must use `"workload_type": "proxy"`, because `kubectl port-forward` only supports TCP. The proxy component routes the UDP traffic.
</Callout>

## Automatic reconnection

kftray monitors all active port forwards and reconnects automatically when:

- Network connectivity drops
- Pods restart or Kubernetes reschedules them
- The Kubernetes API server is briefly unavailable
- The forwarded service scales or updates

Reconnection uses exponential backoff. The wait starts at 1 second and doubles up to 30 seconds between attempts. The interface shows connection status while it reconnects.

See [Workload Types](/docs/configuration/workload-types) to choose between service, pod, proxy and expose modes.

<Callout type="warn" title="Port conflicts">
If the local port is already in use, kftray won't start the forward. Find the conflicting process with `lsof -i :PORT` on macOS or Linux, or `netstat -ano | findstr :PORT` on Windows.
</Callout>

## Practical examples

### Web service debugging

```json
{
  "service": "frontend",
  "local_port": 3000,
  "remote_port": 3000,
  "context": "staging",
  "alias": "Staging Frontend"
}
```

Open `http://localhost:3000` to test changes against staging before they reach production.

### Database access

```json
{
  "service": "mysql",
  "namespace": "databases",
  "local_port": 3306,
  "remote_port": 3306,
  "context": "prod-cluster",
  "alias": "Production MySQL"
}
```

Point your local database client at `localhost:3306` to query production data. Use read-only credentials when you can.

### Microservices debugging

```json
[
  {
    "service": "auth-service",
    "local_port": 8001,
    "remote_port": 8080,
    "context": "dev"
  },
  {
    "service": "user-service",
    "local_port": 8002,
    "remote_port": 8080,
    "context": "dev"
  },
  {
    "service": "payment-service",
    "local_port": 8003,
    "remote_port": 8080,
    "context": "dev"
  }
]
```

Forward several services at once to debug how they talk to each other. Give each service its own local port.
