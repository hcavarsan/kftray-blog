---
title: Auto Import
description: Discover port-forward configurations from Kubernetes service annotations.
---

Auto import reads port-forward configurations from Kubernetes service annotations, so you don't need to create them by hand.

## Annotation format

```yaml
apiVersion: v1
kind: Service
metadata:
  name: api-gateway
  namespace: production
  annotations:
    kftray.app/enabled: "true"
    kftray.app/configs: "api-8080-80,admin-8081-8080"
spec:
  selector:
    app: api-gateway
  ports:
    - name: http
      port: 80
      targetPort: 8080
    - name: admin
      port: 8080
      targetPort: 8080
```

The `kftray.app/configs` annotation defines port forwards in the format `alias-localport-remoteport`. Separate multiple forwards with commas.

This example creates two configurations:

1. `api`: `localhost:8080` → service port `80`
2. `admin`: `localhost:8081` → service port `8080`

## Required annotations

| Annotation | Value | Description |
|------------|-------|-------------|
| `kftray.app/enabled` | `"true"` | Turns on auto import for this service |
| `kftray.app/configs` | `"alias-local-remote,..."` | Comma-separated list of port-forward definitions |

## How discovery works

kftray scans services in every namespace you can access for the `kftray.app/enabled: "true"` annotation. For each annotated service, kftray:

<Steps>
<Step>
Parses the `kftray.app/configs` value.
</Step>
<Step>
Creates a config from the service metadata, your current Kubernetes context and the annotation. The metadata supplies `service` and `namespace`. The annotation supplies `alias`, `local_port` and `remote_port`.
</Step>
<Step>
Adds the configuration to your local database.
</Step>
</Steps>

Discovery runs:

- On kftray startup
- When you trigger "Discover Services" in the interface
- Every 10 minutes (desktop interface only)

<Callout type="warn" title="RBAC permissions required">
Auto import needs permission to list services across namespaces. Check your permissions with `kubectl auth can-i list services --all-namespaces`. Cluster-wide discovery may need a `ClusterRole` binding. If you lack list permission for a namespace, type its name in the import dialog.
</Callout>

## Integration with Helm

```yaml
# templates/service.yaml
apiVersion: v1
kind: Service
metadata:
  name: {{ include "myapp.fullname" . }}
  annotations:
    kftray.app/enabled: "true"
    kftray.app/configs: "{{ .Values.kftray.alias }}-{{ .Values.kftray.localPort }}-{{ .Values.service.port }}"
spec:
  ports:
    - port: {{ .Values.service.port }}
      targetPort: http
```

```yaml
# values.yaml
service:
  port: 8080

kftray:
  alias: "myapp"
  localPort: 8080
```

Deploy with Helm and kftray discovers the service on its own:

```bash
helm install myapp ./myapp
# kftray discovers: myapp-8080-8080
```

## Using auto import

<Tabs items={['Desktop', 'Terminal']}>
<Tab value="Desktop">

<Steps>
<Step>
Open the kftray desktop interface.
</Step>
<Step>
Click "Discover Services" in the toolbar.
</Step>
<Step>
Select the namespaces to scan, or "All Namespaces".
</Step>
<Step>
Click "Scan".
</Step>
<Step>
Review discovered configurations.
</Step>
<Step>
Click "Import Selected".
</Step>
</Steps>

Discovered configurations show up in your port-forward list right away.

</Tab>
<Tab value="Terminal">

Discover annotated services and start their port forwards without opening the TUI:

```bash
# Discover and start all annotated services
kftui --auto-discover --context my-cluster --auto-start --non-interactive

# Save discovered configs to the database for later use
kftui --auto-discover --context my-cluster --save

# Use a custom kubeconfig file
kftui --auto-discover --context my-cluster --kubeconfig /path/to/kubeconfig --auto-start --non-interactive

# Enable alias-as-domain and auto loopback address for all discovered services
kftui \
  --auto-discover \
  --context my-cluster \
  --alias-as-domain \
  --auto-loopback \
  --auto-start \
  --non-interactive
```

</Tab>
</Tabs>
