---
title: GitHub Sync
description: Share port-forward configurations across a team through a GitHub repository.
---

GitHub sync pulls your team's port-forward configs from a shared repository. Commit the JSON once and everyone gets new configs and changes on the next sync.

## Setup

### Create a configuration repository

Export your configs to a JSON file (see [import and export](/docs/configuration#import-and-export)), then commit it to a GitHub repository:

```bash
mkdir kftray-configs
cd kftray-configs
git init

# Create configuration files
cat > production.json <<EOF
[
  {
    "alias": "Production API",
    "service": "api-gateway",
    "namespace": "production",
    "local_port": 8080,
    "remote_port": 80,
    "context": "prod-cluster",
    "workload_type": "service",
    "protocol": "tcp"
  },
  {
    "alias": "Production Database",
    "service": "postgres",
    "namespace": "databases",
    "local_port": 5432,
    "remote_port": 5432,
    "context": "prod-cluster",
    "workload_type": "service",
    "protocol": "tcp"
  }
]
EOF

git add production.json
git commit -m "Add production configurations"
git remote add origin git@github.com:your-org/kftray-configs.git
git push -u origin main
```

### Repository structure

<Files>
<Folder name="kftray-configs" defaultOpen>
<File name="production.json" />
<File name="staging.json" />
<File name="development.json" />
<File name="README.md" />
</Folder>

Each JSON file holds an array of [configuration objects](/docs/configuration). You can organize files by environment, team or service group and sync several of them at once.

kftray uses the repository's default branch. There's no branch setting.

### Configure sync

<Tabs items={['Desktop', 'Terminal']}>
<Tab value="Desktop">

<Steps>
<Step>
Select the GitHub icon (`Configure Git Sync`) in the footer.
</Step>
<Step>
Enter the URL of your repository, for example `https://github.com/your-org/kftray-configs`.
</Step>
<Step>
Enter the path to the JSON config file. If your configs are split across several files, use the `+` button to add more paths.
</Step>
<Step>
Choose `Public Repository`, `Use System Git Credentials` or `GitHub Token`. For a private repository, use system credentials or a token. See [Authentication](#authentication).
</Step>
<Step>
Set the polling interval, the time between automatic syncs.
</Step>
<Step>
Save your settings to start a sync.
</Step>
</Steps>

![GitHub sync dialog with authentication methods, flush option and polling interval](/img/docs/git-sync-dialog.webp)

| Option | Detail |
|--------|--------|
| Polling interval | A slider from 0 to 120 minutes in steps of 5. The default is 60 minutes. `0` turns automatic polling off |
| Flush existing configs before sync | Off by default. Replaces local configs with the repository's set while keeping IDs for matching forwards. Stop forwards first and finish pending cluster cleanup |

kftray saves settings before importing configs. If the import fails, the saved settings still apply, including a polling interval of `0`. The dialog reports `Git sync settings saved` after saving and `Sync Failed` for an import failure.

While Git credentials are configured, `Import Local File` in the footer menu is disabled.

Flush refuses to replace configurations whose forwards are running, starting or still need cluster cleanup. Stop those forwards and retry after cleanup finishes.

</Tab>
<Tab value="Terminal">

Pass the GitHub repository URL and the config file path when you launch kftui:

```bash
kftui --github-url https://github.com/your-org/kftray-configs --configs-path env/production.json
```

To merge configs split across several files, separate the paths with commas:

```bash
kftui --github-url https://github.com/your-org/kftray-configs --configs-path env/production.json,env/shared.json
```

kftui trims spaces around each path, skips empty entries and joins the files into one list. `--github-url` always needs `--configs-path`.

Add `--save` to keep the imported configurations in the database. Without it, kftui keeps them in memory for that run:

```bash
kftui --github-url https://github.com/your-org/kftray-configs --configs-path env/production.json --save
```

For private repositories, kftui uses system Git credentials. You can also set `GITHUB_TOKEN` for an HTTPS repository before launching.

</Tab>
</Tabs>

## Authentication

Public repositories need no token. Private repositories support these authentication methods:

| Method | Credentials |
|--------|-------------|
| `Use System Git Credentials` | SSH agent for SSH repository URLs, or your configured Git credential helper |
| `GitHub Token` | Personal access token that can read the repository, used with an HTTPS URL |

A classic token with the `repo` scope works. Create one in [GitHub token settings](https://github.com/settings/tokens):

<Steps>
<Step>
Click "Generate new token (classic)".
</Step>
<Step>
Name it "kftray sync".
</Step>
<Step>
Set an expiration that fits your security policy.
</Step>
<Step>
Select the `repo` scope.
</Step>
<Step>
Click "Generate token".
</Step>
<Step>
Copy the token right away, because GitHub won't show it again.
</Step>
</Steps>

The desktop app saves the token, with the other sync settings, in the system keyring (Keychain on macOS). kftray doesn't store credentials in any local file.

<Callout type="error" title="Token security">
A personal access token grants access to every repository in its scope. Store tokens securely and rotate them regularly. Never commit tokens to version control or share them in chat.
</Callout>

## Sync behavior

### Periodic checks

The desktop app syncs at the polling interval, 60 minutes by default. Each sync updates your configs one at a time:

<Steps>
<Step>
kftray matches configs by workload type, protocol and the workload's target fields. Kubernetes workloads also require the same context, namespace and kubeconfig.
</Step>
<Step>
A match is updated with the repository's values and keeps its ID. If the repository's alias is blank or its local port is missing or `0`, kftray keeps the old alias or local port.
</Step>
<Step>
A config with no match is added.
</Step>
</Steps>

### How configs match

kftray trims kubeconfig values before matching. Omitted, blank and `default` values match each other.

| Workload | Target fields that must match |
|----------|-------------------------------|
| `service` | `service` |
| `pod` | `target` label selector |
| `proxy` | `remote_address` |
| `expose` | Trimmed `alias` and `local_port`, unless the incoming local port is `0` |
| `ssh-port-forward` | `ssh_provider`, `remote_address` and `remote_port`. Context, namespace and kubeconfig do not affect SSH matching |

For service, pod, proxy and SSH configs, both local and remote ports must also match when both configs have nonzero local ports.

With multiple candidates, kftray ranks matches by remote port, local port and local endpoint. The endpoint includes the local address and enabled domain alias. Ambiguous matches can create a separate config or skip the incoming config.

kftray doesn't delete local configs that are missing from the repository, unless `Flush existing configs before sync` is on.

With flush on, matching forwards keep their IDs and shortcut targets. Flush removes forwards missing from the repository and removes their shortcut targets. kftray deletes a shortcut if it has no targets left. If an incoming config matches several saved ports ambiguously, flush creates a new config instead of choosing an existing one. The old shortcut targets disappear.

### Conflict resolution

Only matching configs receive repository changes. Changing identity fields locally can make the next sync add a separate config instead of updating it.

To keep local changes:

<Steps>
<Step>
Turn polling off by setting the interval to `0`.
</Step>
<Step>
Export your local configurations.
</Step>
<Step>
Merge your changes into the repository and push to GitHub.
</Step>
<Step>
Turn sync back on.
</Step>
</Steps>

### Manual trigger

To fetch the latest configs before the next scheduled check, click the `Sync` button in the footer. Hover over it to see the repository, paths, authentication, interval and the last and next sync times. The button is disabled while a sync runs or when no credentials are configured. A scheduled sync is skipped while another one is running.
