---
title: Proxy Forwarding
description: Route traffic through a Kubernetes cluster to reach internal or external services.
---

Proxy forwarding sends traffic through your Kubernetes cluster to reach services your local machine can't connect to directly.

## Basic proxy configuration

```json
{
  "service": "kftray-server",
  "workload_type": "proxy",
  "remote_address": "internal-api.company.com:443",
  "local_port": 8443,
  "remote_port": 8080,
  "context": "prod-cluster",
  "alias": "Internal API via Proxy"
}
```

This forwards `localhost:8443` through the `kftray-server` proxy pod to `internal-api.company.com:443`.

## The kftray-server proxy component

The `kftray-server` proxy pod runs in your Kubernetes cluster. It receives traffic from your local port forward and sends it to the `remote_address` target.

You need the proxy component for:

- UDP port forwarding
- Reaching services outside the cluster from the cluster network
- Reaching internal corporate services through cluster network policies
- Connecting to services that allow your cluster's outbound IP addresses

kftray deploys the proxy pod automatically when you create a proxy forward. The pod runs in the same namespace as your target service.

<Callout type="warn" title="Cluster permissions required">
Deploying the proxy needs permission to create pods and services in the target namespace. If deployment fails, check your Kubernetes role-based access control (RBAC) permissions with `kubectl auth can-i create pods -n NAMESPACE`.
</Callout>

## Use cases

### Internal corporate APIs

```json
{
  "service": "kftray-server",
  "workload_type": "proxy",
  "remote_address": "hr-api.internal.company.com:8080",
  "local_port": 9000,
  "remote_port": 8080,
  "context": "corp-cluster",
  "namespace": "default"
}
```

This reaches internal APIs through the corporate cluster's network, even when your machine is outside the VPN.

### Cloud services with IP restrictions

```json
{
  "service": "kftray-server",
  "workload_type": "proxy",
  "remote_address": "restricted-api.cloud-provider.com:443",
  "local_port": 8443,
  "remote_port": 8080,
  "context": "prod-cluster",
  "namespace": "production"
}
```

This reaches cloud services that allow your cluster's outbound IP addresses. The traffic comes from the cluster, so your local IP doesn't need access.
