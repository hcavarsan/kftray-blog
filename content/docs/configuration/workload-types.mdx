---
title: Workload Types
description: The four forwarding modes (service, pod, proxy and expose) and when to use each.
---

Choose a workload type based on the target you need to reach and the direction of traffic.

![Workload types: TCP forward, proxy forward, UDP forward and expose traffic paths side by side](/diagrams/workload-types.png)

## Service

```json
{
  "service": "postgres",
  "workload_type": "service",
  "local_port": 5432,
  "remote_port": 5432,
  "context": "dev"
}
```

Service mode forwards traffic through a Kubernetes Service's load balancer to a healthy pod. Use it for most forwards, since it survives pod restarts and scaling.

## Pod

```json
{
  "service": "debug-pod-abc123",
  "workload_type": "pod",
  "target": "app=myapp",
  "local_port": 9229,
  "remote_port": 9229,
  "context": "dev"
}
```

Pod mode forwards directly to one pod, chosen by a label selector or pod name. Use it to debug a particular pod or when no service exists. The forward breaks if the pod restarts.

## Proxy

```json
{
  "service": "kftray-server",
  "workload_type": "proxy",
  "remote_address": "internal-api.company.com:443",
  "local_port": 8443,
  "remote_port": 8080,
  "context": "prod-cluster",
  "namespace": "default"
}
```

Proxy mode routes traffic through a `kftray-server` pod to reach services your machine can't access directly. UDP forwarding also needs this mode, because Kubernetes port-forward only supports TCP.

See [Proxy Forwarding](/docs/configuration/proxy-forwarding) for deployment details and use cases.

## Expose (reverse tunneling)

```json
{
  "alias": "myapp.example.com",
  "namespace": "production",
  "local_port": 3000,
  "local_address": "localhost",
  "context": "my-k8s-cluster",
  "workload_type": "expose",
  "protocol": "tcp",
  "domain_enabled": true,
  "exposure_type": "public",
  "cert_manager_enabled": true,
  "cert_issuer": "letsencrypt-prod",
  "cert_issuer_kind": "ClusterIssuer",
  "ingress_class": "nginx"
}
```

Expose mode makes your local service available to the cluster or the public internet. Traffic goes through the `kftray-server` pod to your machine.

Use cases:

- Testing webhooks from external services against your local development server
- Sharing work-in-progress features with teammates through a URL the cluster can reach
- Running local services that other pods in the cluster need to reach

Set `"exposure_type": "internal"` to make the service reachable only inside the cluster. Set it to `"public"` to create an ingress, with optional TLS through cert-manager.

```json
{
  "alias": "internal-api",
  "namespace": "development",
  "local_port": 8080,
  "local_address": "localhost",
  "context": "my-k8s-cluster",
  "workload_type": "expose",
  "protocol": "tcp",
  "domain_enabled": true,
  "exposure_type": "internal"
}
```

### Expose configuration fields

| Field | Description |
|-------|-------------|
| `exposure_type` | `"internal"` (cluster only) or `"public"` (internet via ingress) |
| `cert_manager_enabled` | Turns on automatic TLS certificates through cert-manager |
| `cert_issuer` | cert-manager issuer name, e.g. `"letsencrypt-prod"` |
| `cert_issuer_kind` | `"Issuer"` or `"ClusterIssuer"` |
| `ingress_class` | Ingress class for public exposure, e.g. `"nginx"` |
