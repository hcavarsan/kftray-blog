A kftray config is a JSON object that defines a port forward and its target.

## Full configuration reference

```json
{
  "service": "my-service",
  "namespace": "production",
  "local_port": 8080,
  "remote_port": 80,
  "context": "prod-cluster",
  "workload_type": "service",
  "protocol": "tcp",
  "alias": "Production API",
  "remote_address": "internal-api.company.com:443",
  "local_address": "127.0.0.1",
  "auto_loopback_address": false,
  "domain_enabled": false,
  "kubeconfig": "/custom/path/to/kubeconfig",
  "target": "specific-pod-name",
  "http_logs_enabled": false,
  "exposure_type": "internal",
  "cert_manager_enabled": false,
  "cert_issuer": "letsencrypt-prod",
  "cert_issuer_kind": "ClusterIssuer",
  "ingress_class": "nginx",
  "tags": { "team": "payments", "env": "prod" }
}
```

Each configuration defines one port forward. To forward several services, create one configuration per service.

| Field | Type | Default | Required | Description |
|-------|------|---------|----------|-------------|
| `service` | string | None | Yes | Name of the Kubernetes service or pod to forward |
| `namespace` | string | `"default"` | No | Kubernetes namespace of the workload |
| `local_port` | number | None | Yes | Port on your local machine |
| `remote_port` | number | None | Yes | Port on the Kubernetes service or pod |
| `context` | string | None | Yes | Kubernetes context from your kubeconfig |
| `workload_type` | string | `"service"` | No | Workload type: `"service"`, `"pod"`, `"proxy"` or `"expose"` |
| `protocol` | string | `"tcp"` | No | Network protocol: `"tcp"` or `"udp"` |
| `alias` | string | None | No | Name shown in the interface |
| `remote_address` | string | None | No | Target address for proxy workloads (see [proxy forwarding](/docs/configuration/proxy-forwarding)) |
| `local_address` | string | `"127.0.0.1"` | No | Local bind address. Use `127.0.0.1` for localhost only and `0.0.0.0` for all interfaces |
| `auto_loopback_address` | boolean | `false` | No | Adds entries to the hosts file for local domains automatically |
| `domain_enabled` | boolean | `false` | No | Turns on local domain resolution |
| `kubeconfig` | string | None | No | Path to a custom kubeconfig file, used instead of the default |
| `target` | string | None | No | Label selector or pod name for pod workloads |
| `http_logs_enabled` | boolean | `false` | No | Turns on HTTP traffic logging for this forward |
| `exposure_type` | string | None | No | For expose workloads: `"internal"` (cluster only) or `"public"` (internet via ingress) |
| `cert_manager_enabled` | boolean | `false` | No | Turns on automatic TLS certificates through cert-manager (expose workloads) |
| `cert_issuer` | string | None | No | cert-manager issuer name, e.g. `"letsencrypt-prod"` |
| `cert_issuer_kind` | string | None | No | cert-manager issuer kind: `"Issuer"` or `"ClusterIssuer"` |
| `ingress_class` | string | None | No | Ingress class for public expose workloads, e.g. `"nginx"` |
| `tags` | object | None | No | Labels as `"key": "value"` pairs, or `"key": ""` for a key without a value. They group and filter configurations (see [tags, filters and group by](/docs/configuration/tags-and-views)) |

## Minimal configuration

```json
{
  "service": "postgres",
  "local_port": 5432,
  "remote_port": 5432,
  "context": "dev-cluster"
}
```

This creates a TCP forward from `localhost:5432` to the `postgres` service in the `default` namespace.

## Storage location

kftray stores all configurations in a SQLite database at `~/.kftray/kftray.db`. The database keeps your port forwards, connection history and settings across restarts.

You don't need to edit this file. The [desktop interface](/docs/interfaces/desktop) and the [terminal interface](/docs/interfaces/terminal) manage configurations for you.

## Sharing configurations

### File export and import

Export configurations as JSON files to share with teammates or back up your setup:

```bash
# Export from desktop interface: File → Export Configurations
# Import from desktop interface: File → Import Configurations
```

The exported JSON is an array of configuration objects:

```json
[
  {
    "service": "api",
    "local_port": 8080,
    "remote_port": 80,
    "context": "prod"
  },
  {
    "service": "database",
    "local_port": 5432,
    "remote_port": 5432,
    "context": "prod"
  }
]
```

### GitHub sync

[GitHub sync](/docs/configuration/github-sync) pulls configs from a repository automatically, so your team can share updates without exchanging files.
