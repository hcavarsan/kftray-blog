The kftray desktop interface manages Kubernetes port forwards visually and runs from the system tray.

![kftray desktop interface](/img/kftools.webp)

## System tray integration

The system tray icon gives quick access without opening the full interface.

On macOS:
```
Menu bar icon → Click for quick menu
Right-click → Start All, Stop All, Open Main Window
```

On Windows:
```
System tray → Click for quick menu
Right-click → Start All, Stop All, Open Main Window
```

On Linux:
```
AppIndicator → Click for quick menu
Right-click → Start All, Stop All, Open Main Window
```

<Callout type="warn" title="Linux AppIndicator requirement">
GNOME needs the AppIndicator extension installed and enabled. KDE, XFCE and other desktop environments usually include AppIndicator support by default.
</Callout>

The tray icon changes color to show whether any forwards are active.

## Main window

The main window lists all configurations, each with a status toggle.

<Accordions>
<Accordion title="Configuration list">
Each entry shows the service name, alias, local and remote ports, namespace and context. A color or error icon shows its status. Use the toggle switch to start or stop the forward.
</Accordion>
<Accordion title="Search, group by and filters">
Search by alias, context, remote address, port or tag. Use the toolbar to group and filter configs by context, namespace, kubeconfig, workload type, protocol or tag key. See [tags, filters and group by](/docs/configuration/tags-and-views).
</Accordion>
<Accordion title="Drag-and-drop">
Drag configurations to reorder them. Group related services together to keep large configuration sets organized.
</Accordion>
</Accordions>

## Configuration management

<Tabs items={['Create', 'Edit', 'Duplicate', 'Delete']}>
<Tab value="Create">

Click the `+` button or press `Ctrl/Cmd + N` to create a new configuration.

Required fields:
```json
{
  "service": "api-gateway",
  "namespace": "development",
  "local_port": 8080,
  "remote_port": 80,
  "protocol": "tcp",
  "alias": "gateway"
}
```

Optional fields:
- Custom kubeconfig path
- Specific context
- Workload type (service, pod, deployment)
- Domain alias for local access

The configuration dialog validates inputs and won't save an invalid configuration.

</Tab>
<Tab value="Edit">

Click the edit icon next to a configuration to change it.

Changes apply immediately to stopped forwards. Restart active forwards to use the new settings.

Common edits:
- Change the local port to avoid conflicts
- Update the alias for clarity
- Switch to a different namespace
- Change the protocol (TCP/UDP)

</Tab>
<Tab value="Duplicate">

Click the duplicate icon next to a configuration to create a copy. This helps when you need a similar forward with a different local port or namespace.

</Tab>
<Tab value="Delete">

To delete one config, click its delete icon and confirm the deletion.

To delete several at once:
1. Select the configurations with the checkboxes.
2. Click the bulk delete button.
3. Confirm the deletion.

kftray stops active forwards before deleting them.

</Tab>
</Tabs>

## Port forward management

To start one forward, toggle the switch next to its configuration. The status changes from red (stopped) to yellow (connecting) to green (active).

To start all forwards, click "Start All" or use the system tray menu.

To stop forwards, use the toggle switches, "Stop All" or the tray menu. Only the app that started a forward can stop it.

Status indicators:

| Color | Meaning |
|-------|---------|
| Green | Active connection |
| Red | Stopped |
| Yellow | Connecting or reconnecting |
| Error icon | Failed to start or lost connection |

When a connection fails, a tooltip shows the error details. Click the error icon for troubleshooting information.

## HTTP logging

HTTP logging records requests and responses for debugging. See [HTTP Logging](/docs/configuration/http-logging) for setup and log formats.

To turn on logging:

<Steps>
<Step>
Right-click a configuration.
</Step>
<Step>
Select "Enable HTTP Logging".
</Step>
<Step>
A toggle switch appears next to the configuration.
</Step>
</Steps>

To view logs, click the log viewer icon next to a configuration with logging enabled. The logs open in your system's default text editor.

Logs live in this directory:
```bash
~/.kftray/http_logs/
```

Each configuration writes its own log file, named like this:
```
config-<id>-port-<local_port>.log
```

<Callout type="info" title="Disk usage">
HTTP logging can produce large files for high-traffic services. Watch disk usage and clean up logs regularly with the bulk cleanup option in the main menu.
</Callout>

## Log viewer

Right-click the system tray icon and select "View Logs" to open the built-in log viewer. It refreshes application logs as they arrive and supports:

- Filtering by log level or module
- Full-text search across log entries
- Browsing older log files
- Exporting logs or generating a diagnostic report to share

You can configure log retention, including how many files to keep and for how long. kftray cleans up old logs automatically on startup.

## Server resources

Click "Server Resources" in the main menu to see the Kubernetes resources kftray has deployed. These include proxy pods, services and ingress objects for expose workloads. Use this view to check resources and remove leftovers.

## GitHub sync

GitHub sync shares configs across a team. See [GitHub Sync](/docs/configuration/github-sync) for authentication and sync behavior.

To set it up:

<Steps>
<Step>
Open Settings → GitHub Sync.
</Step>
<Step>
Enter the repository URL (e.g., `https://github.com/team/kftray-configs`).
</Step>
<Step>
Add a personal access token with the `repo` scope.
</Step>
<Step>
Set the sync interval (default: 5 minutes).
</Step>
<Step>
Turn on the auto-sync toggle.
</Step>
</Steps>

Click "Sync Now" to fetch updates before the next scheduled check.

The repository version overwrites local changes. Back up your configs before turning on sync if you need to keep local settings.

## Auto import

Auto import discovers services in Kubernetes clusters and suggests configurations. See [Auto Import](/docs/configuration/auto-import) for annotation details.

To run it:

<Steps>
<Step>
Click "Auto Import" in the main menu.
</Step>
<Step>
Select the kubeconfig and context.
</Step>
<Step>
Choose the target namespace (or scan all).
</Step>
<Step>
Review the discovered services with the `kftray.app/enabled` annotation.
</Step>
<Step>
Select the services to import.
</Step>
<Step>
Click "Import Selected".
</Step>
</Steps>

Imported configurations merge with existing ones, so running auto import several times creates no duplicates.

## Settings

<Accordions>
<Accordion title="General">
Auto-start at system boot, minimize to tray on close, automatic update checks and interface theme (dark mode by default).
</Accordion>
<Accordion title="Kubernetes">
Default context, custom kubeconfig file path, namespace filtering for auto import and connection timeout (default: 30s).
</Accordion>
<Accordion title="GitHub integration">
Repository URL, personal access token (stored in the system keychain), sync interval and the auto-sync toggle.
</Accordion>
<Accordion title="HTTP logging">
Default log directory, log rotation settings and maximum log file size.
</Accordion>
<Accordion title="Crash reports and performance data">
On first start, kftray asks whether it may send crash reports and port-forward timings to the maintainer. Crash reports start on and performance data starts off. kftray sends nothing before you answer. You can change both switches in Settings later. See [Crash reports](https://github.com/hcavarsan/kftray/blob/main/docs/kftray/USAGE.md#crash-reports) for what a report contains and where it goes.
</Accordion>
</Accordions>
